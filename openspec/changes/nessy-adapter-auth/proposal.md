## Why

Nessy существенно отличается от Qwen, поэтому представление Nessy как Qwen-совместимого провайдера больше не соответствует продукту. Авторизация должна использовать готовый токен из пользовательской конфигурации и не требовать интерактивного запуска Nessy перед работой Stepan.

## What Changes

- **BREAKING**: заменить провайдера `qwen` на `nessy`, без совместимого алиаса; использовать только исполняемый файл `nessy` из PATH и отклонять `--agent-cli-name` для этого провайдера.
- Переименовать адаптер, пользовательскую справку, диагностику и связанные тесты и скрипты приёмки.
- Читать готовый токен только из `nessy.auth_token` в `~/.stepan/settings.json` и передавать его через `NESSY_CLI_DP_AUTH_TOKEN` процессам Nessy, перекрывая унаследованное значение.
- При отсутствии пригодной конфигурации завершать запуск с понятной ошибкой; убрать предварительный интерактивный запуск Nessy.
- Не выполнять команды `dp`, HTTP-обмен токенов или автоматическое обновление JWT. Пользователь самостоятельно получает и заменяет токен.

## Capabilities

### New Capabilities

- `nessy-adapter`: выбор и идентичность провайдера Nessy вместо Qwen.
- `nessy-auth`: авторизация Nessy готовым токеном из пользовательской конфигурации.

### Modified Capabilities

Нет: основной каталог спецификаций пока не содержит спецификаций этих возможностей.

## Impact

Затрагиваются CLI в `cmd/stepan`, адаптер `internal/agentruntime/qwenapp`, его тесты, скрипты приёмки и актуальная документация. Новый пользовательский контракт конфигурации — `~/.stepan/settings.json`. Общий ACP-контракт, ограничения инструментов и управление процессами сохраняются; внешние имена параметров Nessy нельзя менять простой заменой слова Qwen без проверки их поддержки.

Stepan получает из файла конфигурации уже готовое значение для переменной окружения Nessy.
