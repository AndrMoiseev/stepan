## Why

Настройки Stepan сейчас разрешаются в разных пакетах: `usersettings` читает токен Nessy, `implementationconfig` объединяет пользовательскую и проектную секции, а bootstrap отдельно разбирает и записывает тот же JSON. Профили агентского runtime при этом вложены в `implementation`, хотя их смысл не зависит от одного flow. Единый модуль настроек должен владеть форматом, приоритетом источников и выдавать потребителям уже разрешённые значения.

## What Changes

- **BREAKING**: заменить секции `implementation` и `nessy` на `flows.impl_loop` и `agentruntime.nessyapp`; перенести общие профили в `agentruntime.profiles`. Старые секции вызывают явную ошибку конфигурации; чтение прежней схемы и автоматическая миграция не предусматриваются.
- Ввести `internal/setting` как единый интерфейс доступа к эффективным настройкам и перенести в него ответственность `usersettings` и `implementationconfig`. Чтение двух файлов, слияние, значения по умолчанию и разрешение профилей остаются внутри модуля; потребители получают типизированные значения без повторного разбора исходного JSON.
- Сохранить правила приоритета пользовательских и проектных значений, проектный характер проверок, файла правил и основной ветки, а также фиксацию настроек активного run до resume.
- Читать токен Nessy из нового пользовательского пути только при выборе Nessy. Не включать секрет в снимок эффективных настроек, предложения bootstrap, diff или артефакты run.
- Перевести bootstrap на новую структуру предложений и проверку через `setting`, сохранив подтверждение пользователем перед записью.

## Capabilities

### New Capabilities

- `settings`: единый контракт эффективных настроек, иерархия секций, слияние источников, профили, flow-настройки и безопасный доступ к токену Nessy.

### Modified Capabilities

Отсутствуют: основной каталог `openspec/specs/` пока не содержит соответствующих capabilities. Эта отдельная спецификация задаёт новый контракт вместо путей, описанных в незавершённых изменениях `autonomous-implementation-loop` и `nessy-adapter-auth`; перед применением этих изменений их противоречащие требования нужно согласовать.

## Impact

Затрагиваются `internal/usersettings`, `internal/implementationconfig`, конфигурационная часть `internal/flows/impl_loop`, сборка runtime в `cmd/stepan` и `internal/implementationruntime`, bootstrap, архитектурные правила, пользовательские примеры JSON и диагностика ошибок. Выбор провайдера в `flows/spec` остаётся CLI-контрактом; общий реестр профилей становится доступным другим flow без обязательного перевода их на профили в этом изменении.
