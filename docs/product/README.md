# Документация продукта Stepan

Статус: согласованный исходный набор продуктовых требований; архитектурные решения ожидают ADR  
Дата: 2026-08-08  
Методологическая основа: «Инженерия надёжных фреймворков на AI-агентах»

## С чего начать

- [Краткий продуктовый бриф](product-brief.md) — зачем существует продукт, для кого он создаётся, что входит в scope и каким должен быть результат.
- [Реестр решений и предположений](product-decisions.md) — уже принятые продуктовые решения и допущения, которые ещё должны быть проверены.
- [Каталог требований](requirements/README.md) — нормативные требования, разделённые по направлениям.
- [Этапы поставки и критерии приёмки](requirements/roadmap-and-acceptance.md) — состав и end-to-end критерии P0–P3.
- [Трассировка к методологии](requirements/traceability.md) — связь требований с исходной методологией и следующие проектные артефакты.

## Статус документов

Документы в `requirements/` вместе образуют один нормативный набор. Границы файлов нужны для навигации и владения направлениями и не меняют приоритет требований. Конкретные архитектурные решения должны быть зафиксированы отдельно в ADR и не могут молча переопределять требования.

Файл [initial-requirements.md](initial-requirements.md) сохранён как совместимая точка входа для старых ссылок, но больше не содержит отдельную копию требований.
