# Stepan: план совместимости с macOS

Статус: реализация завершена; нативная ручная приёмка ожидается

Дата: 24 августа 2026 года

Целевая среда: macOS native/arm64 (Apple Silicon), `codex-cli 0.147.0`

Связанная проверка: [план ручного тестирования](manual-test-plan.md)

## 1. Цель и ожидаемый результат

После реализации Stepan должен нативно собираться и выполнять существующий
интерактивный flow `/feature` на Apple Silicon Mac. Поведение flow, ограничения на
запись и pinned-версия Codex остаются такими же, как на Windows.

Поддерживаемая матрица после изменения:

| Платформа | Статус | Контроль дерева Codex |
|---|---|---|
| Windows/amd64 | поддерживается без изменений | Windows Job Object |
| macOS/arm64 | новая поддерживаемая платформа | отдельная process group |
| macOS/amd64 | вне текущего scope | — |
| Linux | вне текущего scope | — |

Критерий готовности macOS — успешное прохождение отдельного ручного плана на
физическом Apple Silicon Mac. Новые автоматические тесты и macOS CI в эту работу
не входят.

## 2. Зафиксированные технические решения

### 2.1. Процесс Codex

- Stepan продолжает напрямую использовать `codex app-server --stdio`; переход
  на ACP или запуск отдельного внешнего daemon не входит в эту работу.
- До `cmd.Start()` дочерний процесс на macOS помещается в новую process group
  через `SysProcAttr.Setpgid`.
- После старта Stepan сохраняет PGID. При закрытии supervisor отправляет
  `SIGKILL` всей группе, а не только непосредственному процессу.
- Штатный путь завершения остаётся двухфазным: сначала `turn/interrupt`, затем
  существующее ожидание до трёх секунд, после чего закрывается supervisor.
- `ESRCH` при повторном закрытии считается успешным результатом. Нельзя
  отправлять сигнал собственной process group Stepan; подозрительный или
  неизвестный PGID завершает операцию ошибкой.
- Ошибка настройки либо назначения containment является fail-closed: flow не
  начинается, а уже запущенный непосредственный процесс завершается.

Process group даёт более слабую гарантию, чем Windows Job Object: потомок,
который намеренно создаст новую session/process group, может выйти из неё. Для
текущей интеграции с Codex это принимается как остаточный риск и должно быть
зафиксировано отдельным ADR. Устранение этого риска потребует внешнего
supervisor/`launchd`-архитектуры и не входит в текущий scope.

### 2.2. Терминал и платформа

- Один общий platform helper должен принимать только `windows/amd64` и
  `darwin/arm64`, чтобы проверки в executable и App Server preflight не
  расходились.
- Ошибки preflight должны перечислять обе поддерживаемые платформы и не
  упоминать Windows console при запуске на macOS.
- Проверка интерактивности stdin/stdout на macOS выполняется переносимым TTY
  detector из уже используемого terminal-стека. Зависимость должна стать
  прямой в `go.mod`.
- Запуск с redirected stdin или stdout по-прежнему отклоняется до начала flow.

### 2.3. Совместимость прикладного flow

На macOS сохраняются без ослабления:

- поиск канонического Git root;
- разрешённый путь записи `docs/changes/features/<feature-id>/`;
- защита от выхода через symlink;
- read-only turns для уточнений и вопросов;
- write-boundary для создания и изменения спецификации;
- точная версия `codex-cli 0.147.0`;
- ленивый старт App Server, переиспользование процесса между flow и новый
  процесс после сбоя.

## 3. Что не входит в работу

- поддержка Intel Mac (`darwin/amd64`) и Linux;
- installer, Homebrew formula, universal binary;
- code signing, notarization и публикация артефактов;
- macOS CI и любые новые автоматические тесты;
- смена версии Codex или ослабление version pin;
- миграция с Codex App Server на ACP SDK;
- изменение UX или функциональности `/feature`.

### MAC-01. Единая матрица платформ

**Результат:** executable и `internal/agentruntime/codexapp` одинаково принимают
Windows/amd64 и macOS/arm64.

**Изменения:**

- [x] Выделить маленький общий helper с матрицей платформ и текстом требования.
- [x] Перевести `cmd/stepan` и App Server preflight на этот helper.
- [x] Оставить все остальные комбинации неподдерживаемыми.
- [x] Проверить, что версия Codex валидируется только после platform preflight.

**Критерии приёмки:**

- macOS/arm64 больше не получает `unsupported platform`;
- Windows/amd64 продолжает приниматься;
- ошибка для неподдерживаемой комбинации явно называет обе поддерживаемые цели.

### MAC-02. Supervisor на базе process group

**Результат:** `internal/processjob` умеет подготовить процесс macOS до старта и
закрыть всю унаследованную process group.

**Изменения:**

- [x] Расширить lifecycle supervisor операцией подготовки `exec.Cmd` до
  `Start`; Windows-реализация этой операции остаётся no-op.
- [x] Добавить `job_darwin.go` с `Setpgid`, получением/валидацией PGID и
  групповым `SIGKILL`.
- [x] Ограничить текущий fallback-файл build tag-ом `!windows && !darwin`.
- [x] Сделать `Close` потокобезопасным, повторно вызываемым и tolerant к уже
  завершившейся группе.
- [x] Зафиксировать различие гарантий Windows Job Object и Darwin process group
  в новом ADR; существующий ADR 0001 не переписывать задним числом.

**Критерии приёмки:**

- новая process group создаётся до выполнения кода дочернего процесса;
- сохранённый PGID не совпадает с process group Stepan;
- закрытие supervisor завершает App Server и его обычных потомков;
- partial-start и repeated-close paths не оставляют процесс Codex.

### MAC-03. Подключение supervisor ко всем запускам Codex

**Результат:** новый pre-start lifecycle используется долгоживущим App Server.

**Изменения:**

- [x] Вызывать подготовку supervisor до `Start` в
  `internal/agentruntime/codexapp/process.go`.
- [x] На ошибке назначения сначала закрывать supervisor, затем завершать и
  дожидаться непосредственного процесса.
- [x] Сохранить текущий порядок закрытия stdio и ожидания процесса, чтобы не
  получить зависание на pipe.
- [x] Не менять протокол, prompts, approval policy и timeout-ы.

**Критерии приёмки:**

- `Ctrl+C` во время turn сначала инициирует protocol interrupt, затем удаляет
  оставшуюся process group;
- normal close, crash и ошибка старта не оставляют обычных потомков Codex;
- после сбоя следующая команда `/feature` создаёт новый рабочий App Server.

### MAC-04. Интерактивный терминал macOS

**Результат:** нативный Terminal/iTerm2 принимается, перенаправленные потоки
отклоняются.

**Изменения:**

- [x] Заменить безусловный `false` в non-Windows console helper на TTY detector
  для Darwin.
- [x] Сохранить существующую Windows-проверку либо перевести обе платформы на
  один доказанно совместимый helper.
- [x] Сделать сообщения об ошибках платформенно нейтральными: `terminal`, а не
  `Windows console`.
- [x] Отразить прямое использование terminal dependency в `go.mod`/`go.sum`.

**Критерии приёмки:**

- приложение показывает `Command` в нативном интерактивном терминале macOS;
- redirected stdin и redirected stdout завершаются кодом 2 до старта Codex;
- `Ctrl+C` возвращает код 130.
