# Nessy: приёмка адаптера и авторизации

Для каждого сценария записать PASS, FAIL или BLOCKED, ОС/архитектуру, версию
Go и Nessy. Не сохранять токен, полный environment или содержимое settings.json
в отчёт. Использовать безопасные отчёты runner. Пропуск не является PASS.

## Подготовка

Нужны Go 1.26.5, Git, Nessy в PATH и действующий токен, вручную записанный в
`~/.stepan/settings.json` в строковое поле `nessy.auth_token`. Пример без
действительного секрета находится в README. Для macOS требуется физический
Apple Silicon Mac; cross-build проверяет только компиляцию.

## Автоматическая приёмка

Windows/amd64, из корня репозитория:

```powershell
go test ./...
go build -o stepan.exe ./cmd/stepan
./scripts/test-nessy-conformance.ps1
```

На физическом Apple Silicon Mac:

```sh
go test ./...
go build -o stepan ./cmd/stepan
bash scripts/test-nessy-conformance.sh
```

Оба runner запускают только `nessy`, без `--agent-cli-name`. Реальные тесты
используют тот же загрузчик домашнего файла, подставляют конфликтующее значение
в родительское окружение и проверяют окружение запуска каждого процесса.
Проверки включают ACP, пять разрешённых инструментов, запреты дополнительных
возможностей, файловую политику, flow/rework/resume и завершение дерева
процессов Windows или process group macOS.

## Пользовательские сценарии

1. Запустить `stepan --agent nessy` с настроенным токеном. Не должно быть
   предварительного CLI входа; пройти intent/spec/plan с reviewer и resume.
2. Проверить ошибки `--agent qwen`, `--agent nessy --agent-cli-name nessy` и
   `--agent nessy --agent-cli-name=`: ни один агент не запускается, ошибка
   объясняет поддерживаемый вызов.
3. На отдельном тестовом домашнем каталоге проверить отсутствующий файл,
   malformed JSON, отсутствующий/нестроковый/пробельный токен. Даже при
   установленной `NESSY_CLI_DP_AUTH_TOKEN` запуск Nessy должен завершиться
   ошибкой с путём и именем поля, без содержимого настроек.
4. С отсутствующими или неверными Nessy-настройками проверить запуск Codex и
   Claude. Их выбор и override остаются прежними.
5. При отказе Nessy из-за недействительного токена убедиться, что Stepan не
   запускает login/refresh. После ручной замены токена перезапустить Stepan.
6. Проверить безопасный JSON-отчёт runner и артефакты flow: токен отсутствует.
   В unit/fake тестах отдельно проверяются утечки через stderr и ACP-ответы.

## Внешние параметры CLI

До PASS записать версию установленного Nessy и доказательства поддержки:

| Параметры | Требуемое поведение | Статус |
| --- | --- | --- |
| `--acp`, `--append-system-prompt` | ACP и заданный JSON-контракт | Не проверено |
| `--approval-mode default`, `--core-tools`, `--exclude-tools` | Пять разрешённых инструментов, ограничения сохраняются | Не проверено |
| `--extensions none`, `--include-directories` | Без расширений, корректный transport root | Не проверено |
| `QWEN_CODE_DISABLE_CRON=1` | Cron отключён | Не проверено |
| `QWEN_CODE_ENABLE_AGENT_TEAM=0` | Agent team отключён | Не проверено |
| `QWEN_CODE_DISABLE_ARTIFACT=1` | Дополнительные artifact-возможности отключены | Не проверено |
| `QWEN_CODE_EMIT_TOOL_USE_SUMMARIES=0` | Дополнительные tool summaries отключены | Не проверено |
| `NESSY_CLI_DP_AUTH_TOKEN` | Готовый токен, без интерактивного входа | Не проверено |

Имена `QWEN_CODE_*` сохранены как внешние параметры прежнего запуска, а не
подтверждённый контракт Nessy. Сверить справку/доступные исходники целевой
версии с эффективным поведением conformance probes. Не заменять имена
механически и не отключать проверки при несовместимости.

## Состояние приёмки

Реальная приёмка пока не выполнена. Для Windows требуется доступная команда
Nessy и домашний токен; для macOS — физический Apple Silicon Mac. Результаты
сборок и fake-тестов фиксируются отдельно и не закрывают эти требования.
