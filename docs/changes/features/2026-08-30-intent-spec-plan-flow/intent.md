# Stepan: flow intent → spec → plan

Статус: черновик

## Проблема и контекст

Текущий `/feature` заканчивается после уточнения intent. Состояние диалога
живёт в памяти процесса, незавершённый flow нельзя возобновить, а дальнейшие
specification и planning не управляются единым детерминированным control plane.

Для сложных specification и implementation plan одного пользовательского
прочтения недостаточно: пользователю нужна возможность по запросу привлечь
отдельного reviewer-агента, обсудить только материальные решения и передать
согласованные исправления исходному author-агенту. При этом agent review не
должен забирать у пользователя окончательное решение.

Содержательные инструкции авторов и reviewer-ов со временем должны
кастомизироваться. Их нельзя смешивать с незаменяемыми системными контрактами,
которые определяют порядок стадий, файловые полномочия и машинный протокол.

## Ожидаемый наблюдаемый результат

Stepan ведёт одну feature через фиксированный порядок `intent → spec → plan`.
Каждая стадия поддерживает продолжительный author-диалог, публикацию draft,
пользовательский approval и отдельный phase commit. Specification и plan также
поддерживают необязательный agent review, reviewer dialogue и ограниченный
автоматический rework-loop.

Flow переживает завершение пользовательского сеанса: опубликованные документы,
review-артефакты, append-only журнал и durable state позволяют продолжить его с
новой agent session. Если живая сессия ещё доступна, Stepan переиспользует её.

Системные prompts остаются неизменяемыми. Role prompts и capability-модули
имеют стабильные логические идентификаторы и в будущем смогут разрешаться из
кастомизируемых источников без изменения control plane.

## Scope

- стадии intent, specification и planning;
- отдельные роли `intent-author`, `spec-author`, `spec-reviewer`,
  `plan-author`, `plan-reviewer`;
- пользовательские revision decision, agent review и stage approval;
- durable state, resume и восстановление agent sessions из артефактов;
- машинно-проверяемые ID и трассировка документов;
- phase commit после каждой утверждённой стадии;
- разделение system, role и capability prompts;
- одинаковая семантика для поддерживаемых agent runtimes.

## Exclusions

- выполнение задач implementation plan;
- детерминированные проверки реализованного кода;
- documentation stage после реализации;
- пользовательская настройка prompt sources в первой версии;
- хранение или восстановление provider thread handles между процессами;
- параллельное выполнение нескольких активных стадий;
- архивирование каждой редакции intent, spec или plan отдельным файлом.

## Существенные ограничения

- пользователь остаётся единственным источником материальных продуктовых и
  архитектурных решений;
- workspace агента остаётся read-only, project-owned файлы пишет только Stepan;
- новый flow начинается только на чистом рабочем дереве;
- в один момент только одна feature может иметь незакоммиченные изменения;
- возврат от spec или plan к intent запрещён: существенное изменение intent
  создаёт новую feature;
- provider-specific ограничения не должны менять семантику flow.
