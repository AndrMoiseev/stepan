# Stepan: ручная приёмка Claude Code-совместимого CLI

Статус: **BLOCKED** до доступа к Claude Code или корпоративному форку. Код и
fake-тесты реализованы, но live-проверка на текущем компьютере отложена.

Связанные документы:

## 1. Контракт первой версии

- Stepan использует `claude-agent-sdk-go`. Без `--agent-cli-name` он разрешает
  официальное имя `claude` через `PATH`; supplied simple executable name также
  разрешается через `PATH`, после чего SDK получает найденный абсолютный путь.
- Явно заданное имя авторитетно. Stepan не подменяет отсутствующий executable
  именем `claude` и не требует официального basename или branding строки версии.
- Совместимость определяется поддержкой требуемого Claude Agent SDK protocol и
  подтверждается этим планом на конкретной версии корпоративного форка.
- Claude разрешены только `Read`, `Write`, `Edit`, `Glob` и `Grep`. `Bash`, MCP,
  hooks, plugins, background tasks и сетевые инструменты отключены.
- Внешние инструменты запускает Stepan вне процесса Claude. Claude запрашивает
  такой запуск структурированным результатом, после чего получает результат в
  следующем ходе.
- В первой версии Stepan полагается на штатное завершение процесса SDK и не
  управляет деревом процессов Claude самостоятельно.

## 2. Стенд и evidence

Используйте одноразовый чистый Git working tree и две консоли: одну для Stepan,
вторую для наблюдения за процессами. Корпоративный CLI должен быть заранее
доступен в изолированном `PATH` под простым именем, отличным от `claude`.
Необходимые credentials должны быть настроены в доверенном user source
`~/.claude/settings.json`; их значения нельзя включать в evidence.

Перед тестом зафиксируйте:

- commit Stepan;
- OS и архитектуру;
- версию `claude-agent-sdk-go`;
- переданное имя, разрешённый абсолютный путь, версию и build ID корпоративного
  CLI;
- effective allowlist инструментов Claude;
- факт загрузки только user setting source без содержимого settings;
- список процессов до запуска.

Проверьте обе поддерживаемые формы запуска Claude runtime:

```text
stepan --agent claude
stepan --agent claude --agent-cli-name corporate-claude-compatible
```

Наблюдение за процессами:

```powershell
# Windows PowerShell: PID CLI и потомки
Get-CimInstance Win32_Process | Where-Object { $_.ParentProcessId -eq <cli-pid> -or $_.ProcessId -eq <cli-pid> }
```

```sh
# macOS: PID CLI и дерево потомков
ps -axo pid,ppid,command | awk '$2 == <cli-pid> || $1 == <cli-pid>'
```

Для каждого сценария поставьте `PASS`, `FAIL` или `BLOCKED` и приложите stdout,
stderr и снимки процессов. Не удаляйте оставшиеся процессы до сбора evidence.

## 3. Сценарии

### CLAUDE-M01. Авторитетное имя executable в PATH

1. Поместите совместимый корпоративный CLI под нестандартным простым именем и
   отдельный fake executable с именем `claude` в тестовый `PATH`.
2. Запустите Stepan с `--agent claude --agent-cli-name
   corporate-claude-compatible` и выполните короткий read-only ход.
3. Замените `claude` в `PATH` совместимым CLI и повторите ход без
   `--agent-cli-name`.
4. Повторите preflight с отсутствующим в `PATH` именем, абсолютным путём и
   значением `--agent-cli-name=`.

Ожидается:

- первый ход обслуживает exact named корпоративный executable, fake `claude` не
  запускается как fallback;
- форма без `--agent-cli-name` запускает официальное имя `claude` из `PATH`;
- нестандартное simple name работает без shell и branding/version gate;
- missing name, путь и явно пустое значение приводят к понятной ошибке до
  создания сессии и не включают fallback;
- в диагностике видны выбранное имя или безопасный разрешённый путь без секретов.

### CLAUDE-M02. Граница встроенных инструментов

1. Создайте marker-файл в проекте и отдельный canary-файл вне Git root.
2. Попросите Claude прочитать marker-файл и изменить разрешённый файл проекта.
3. Попросите прочитать внешний canary, запустить тесты, обратиться к сети и
   вызвать произвольную shell-команду.
4. Просмотрите события SDK, процессы и итоговый Git diff.

Ожидается:

- чтение и запись выполняются встроенными файловыми инструментами;
- содержимое canary вне Git root не попадает в ответ или файлы проекта;
- Claude не может вызвать `Bash`, MCP, hook, plugin или сетевой инструмент;
- запрос тестов возвращается Stepan как структурированный запрос внешнего
  инструмента и исполняется только Stepan-controlled runner;
- изменения не выходят за разрешённые пути проекта;
- под процессом Claude не появляются процессы внешних инструментов.

### CLAUDE-M03. Штатное закрытие и отмена

1. Запустите ход, дождитесь появления процесса настроенного CLI и запишите его
   PID вместе со всеми текущими потомками.
2. Завершите ход штатно, закройте Stepan и убедитесь, что PID CLI исчез.
3. Снова запустите заведомо долгий read/write-only ход и отмените его через
   `Ctrl+C` или предусмотренную UI-команду.
4. Сразу после отмены и ещё раз через 10 секунд снимите список процессов и hash
   working tree.

Ожидается:

- Stepan не зависает при штатном закрытии или отмене;
- процесс CLI завершается;
- после отмены не остаётся процессов, появившихся под CLI во время хода;
- после контрольной точки файлы проекта больше не изменяются;
- новый запуск Stepan создаёт работоспособную независимую сессию.

Если после отмены остаётся процесс или продолжается изменение файлов, сценарий
получает `FAIL`, а собственный process-tree containment становится обязательной
частью Claude-адаптера до выпуска.
