# ADR 0005: Десктопное приложение на Wails и TypeScript

Статус: **принято**

Дата: 2026-09-19

## Контекст

Stepan уже работает как локальный CLI на Go. Его flow, в том числе
`internal/flows/impl_loop`, управляют агентами, Git и состоянием run. Нужна
десктопная точка входа к этому же ядру; CLI остаётся самостоятельным способом
работы. Целевые платформы — Windows/amd64 и macOS/arm64. Первоначальное
распространение будет ручным, но стек должен позволять добавить установщики.

Нынешний `cmd/stepan` требует интерактивный терминал, поэтому запуск готового
CLI из окна не является способом повторного использования ядра. Стек должен
позволять новой точке входа обращаться к Go-пакетам непосредственно.

## Решение

- Десктопную оболочку строим на **Wails**. Это локальное десктопное приложение
  с собственным окном и системным WebView, а не размещённый в браузере сервис.
- Интерфейс пишем на **TypeScript**. Он вызывает ограниченные операции Go через
  мост Wails; прикладные flow, доступ к Git, файловой системе и агентским CLI
  остаются в Go. Десктопная точка входа использует общее Go-ядро непосредственно,
  без отдельного процесса ядра и сетевого API между интерфейсом и Go.
- Поддерживаем Windows/amd64 и macOS/arm64. Для десктопного приложения
  предусматриваем отдельные нативные сборки в GitHub Actions на Windows и
  Apple Silicon runners. Сборка и тесты существующего CLI остаются отдельными.
- На первом этапе распространяем артефакты вручную. Выбранный стек допускает
  последующее создание установщиков; их формат, подпись и способ обновления
  будут определены отдельно.

Конкретную версию Wails и библиотеку интерфейса выбираем при проектировании
десктопного приложения. На дату решения Wails v2 — стабильная ветка, а v3
остаётся beta; ADR не закрепляет major-версию заранее. Структуру экранов и
контракты операций этот ADR также не определяет. `impl_loop` служит примером
проверки пригодности стека, а не ограничением области будущего GUI.

## Рассмотренные варианты

- **Fyne** оставляет интерфейс на Go, но не использует принятый здесь
  TypeScript/WebView-подход к интерфейсу. Его графический стек также требует
  C toolchain для сборки.
- **Tauri** использует Rust как основу приложения. Сохранение существующего
  Go-ядра потребовало бы отдельного Go-процесса и межпроцессного протокола,
  что добавило бы новую границу жизненного цикла и упаковки.

## Последствия

- Сборка GUI добавит Node.js/npm и платформенные зависимости Wails. Текущая
  кросс-сборка CLI с `CGO_ENABLED=0` не заменяет нативную сборку GUI для macOS.
- На Windows приложению нужен WebView2 Runtime. Способ обработки его отсутствия
  выбирается при подготовке дистрибутива.
- Артефакт GitHub Actions подтверждает сборку, но работоспособность и поведение
  дочерних процессов на macOS по-прежнему требуют проверки на Apple Silicon Mac.
- При проектировании GUI нужно выделить из терминальной точки входа
  необходимую композицию и открыть интерфейсу только операции конкретных flow.
