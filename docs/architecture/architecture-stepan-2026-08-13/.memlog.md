---
scope: Целевая архитектура Stepan
purpose: Компактный build substrate для разработчиков
altitude: initiative
created: 2026-08-13
---

- [event] Запущен Coaching path; единственный deliverable — компактный architecture spine.
- [constraint] Stepan остаётся локальным детерминированным control plane над внешними агентскими CLI.
- [constraint] Stepan не реализует собственный agent runtime и не вызывает model API напрямую.
- [constraint] Целевая архитектура обязана поддерживать несколько агентских CLI; второй CLI следует реализовать end-to-end до стабилизации общего runner contract.
- [constraint] Целевые платформы включают как минимум Windows и macOS.
- [constraint] Workflow state, Git facts и результаты проверок авторитетнее состояния и текста агента.
- [question] Какой второй агентский CLI будет первой реальной реализацией после Codex?
- [decision] Claude Code выбран второй целевой CLI-интеграцией; это связывает первый общий runner contract и предотвращает проектирование только под Codex.
- [assumption] До доступа к Claude Code его адаптер проектируется по официальной документации; все непроверенные protocol, lifecycle, permission и resume свойства остаются provisional.
- [constraint] Общий runner contract нельзя объявлять стабильным, пока Codex и Claude Code не проходят одну conformance suite на реально поддерживаемых платформах.
- [direction] Обсуждается capability-aware agent port: минимальный общий invocation contract, явные provider/Stepan/unverified guarantees и fail-closed проверка требований workflow до запуска.
- [decision] Вместо capability matrix все поддерживаемые agent adapters реализуют один обязательный контракт; это связывает workflow с едиными гарантиями и предотвращает provider-specific ветвления.
- [constraint] Адаптер, который не может обеспечить полный обязательный контракт, считается неподдерживаемым; тихое ослабление гарантий запрещено.
- [constraint] Контракт Claude Code остаётся provisional до live conformance tests, даже если соответствующие возможности описаны в официальной документации.
- [decision] Платформенная граница оформляется одним пакетом processcontrol с общей семантикой и build-tagged реализациями для Windows и macOS; это предотвращает кросс-произведение agent×OS.
- [decision] Windows использует Job Object, macOS — POSIX process group и сигналы; обе реализации обязаны завершать всё дерево процесса и проходить одинаковую platform conformance suite.
- [constraint] Workflow и agent adapters не ветвятся по runtime.GOOS и не импортируют OS-specific реализацию напрямую.
- [constraint] Поддержка платформы включается только после live-проверки lifecycle, cancel и cleanup на этой платформе.
- [decision] Durable run state сначала хранится в файловом runstore под `.stepan/runs/<run-id>/`; это связывает recovery с локальными artifacts без БД и миграций.
- [decision] Storage interface не вводится до появления второго реального backend; workflow использует конкретный runstore package, а durable domain records не зависят от формата хранения.
- [constraint] Начальная реализация допускает один writer и последовательное выполнение; состояние и artifacts изолируются по run-id, чтобы не создавать глобальную схему, несовместимую с будущим параллелизмом.
- [direction] При появлении параллельных runs пересмотреть single-writer coordination и только тогда выбирать per-run locks, SQLite или другой backend по измеренным требованиям.
- [decision] Append-only `events.jsonl` является единственным источником durable workflow state; состояние восстанавливается replay событий, snapshot добавляется только при измеримой необходимости.
- [constraint] Событие считается committed только после успешного append и file sync; неполный хвост журнала обнаруживается и не трактуется как committed transition.
- [constraint] Необратимое или наблюдаемое внешнее действие обрамляется durable intent и terminal event; recovery сверяет незавершённый intent с Git и evidence до retry или halt.
- [decision] Встроенные workflow реализуются явными Go state machines; универсальный workflow engine и DSL не создаются до появления минимум двух реальных workflow с доказанным повторением.
- [constraint] Только workflow state machine принимает команды, выпускает durable events и определяет переходы; UI и agent adapters не меняют workflow state напрямую.
- [constraint] Внешние эффекты исполняются императивной оболочкой после committed intent; результат эффекта возвращается в state machine новой командой и terminal event.
- [decision] Stepan-owned execution controller обрамляет каждый agent turn: durable intent, role workspace, access policy, runner invocation, independent verification/evidence и terminal event.
- [constraint] Agent adapters переводят общую access policy в provider-specific механизмы и обязаны отказать до turn, если не могут обеспечить её; native agent sandbox не является владельцем политики.
- [constraint] Write integrity проверяется превентивными ограничениями и независимым Git snapshot/diff после turn; сообщение агента не является evidence.
- [constraint] Read и network confidentiality обеспечиваются до запуска OS/provider controls; post-check не считается защитой. Source-blind role workspace должен быть недоступен исходному checkout на уровне эффективных прав, а не только находиться в другом каталоге.
- [decision] Один run может назначать разные agent adapters разным workflow roles; routing является частью control plane, а не provider-specific workflow logic.
- [constraint] Каждая role execution использует отдельную opaque agent session; session ID принадлежит адаптеру и сохраняется только как ссылка для resume.
- [constraint] Межролевой handoff выполняется только через durable artifacts, committed workflow events и явные prompt inputs; скрытый контекст agent session не является входом другой роли или источником истины.
- [constraint] Потеря или невозможность resume agent session не должна делать run невосстановимым: роль можно перезапустить из durable inputs с явным retry event.
- [question] Отложено: как назначаются adapters ролям — статическим profile, оператором при старте или автоматическим routing; решение требуется до реализации multi-agent selection.
- [constraint] Независимо от механизма выбора фактическое назначение role→runner/version/config фиксируется durable event до первого turn роли; неявный fallback запрещён.
- [direction] Предлагается разделить extension policy: разрешать выбранные user skills как инструкции/resources, запрещать lifecycle hooks и MCP, а skill shell preprocessing/implicit executable extensions держать выключенными.
- [constraint] Если skills разрешены, их resolved path/source и content fingerprint фиксируются до turn; изменение набора или содержимого требует нового execution profile event.
- [assumption] Точный способ selective skill loading в Claude Code остаётся provisional до live test; документированы независимые controls для hooks, MCP и skill shell execution, но их совместное поведение Stepan ещё не проверял.
- [question] Extension policy отложена до проектирования execution profiles: рассмотреть (1) полностью чистый профиль, (2) allowlist skills с запрещёнными hooks/MCP/skill shell execution, (3) явное наследование пользовательского профиля как ослабленный режим. До решения ни один вариант не является архитектурным default.
- [decision] Целевая парадигма — модульный монолит с облегчёнными ports and adapters; пакеты группируются по возможностям, а не по глобальным техническим слоям.
- [decision] Минимальный structural seed: workflow, agent с codex/claude adapters, execution, runstore, gitrepo и processcontrol; каталоги-ярлыки ports/adapters/services/repositories не создаются.
- [constraint] Workflow зависит от общего agent port и доменных records, но не импортирует конкретные agent adapters, storage format, Git CLI или OS-specific process implementation; composition выполняется в cmd/stepan.
- [constraint] Интерфейс объявляет потребляющий пакет только при наличии реальной сменной реализации или тестового шва; пакет не получает интерфейс только ради соответствия архитектурному шаблону.
- [decision] Agent получает право напрямую изменять файлы в подготовленном workspace; Stepan не вводит общий patch-return/apply protocol.
- [constraint] Execution controller передаёт runner канонический workspace root и policy, а gitrepo независимо сравнивает snapshots до/после и отклоняет изменения вне разрешённого write-set.
- [constraint] Source-blind роль выполняется в отдельно материализованном workspace только с разрешёнными inputs и без эффективного доступа к исходному checkout.
- [decision] На первом этапе обычные роли работают последовательно в текущем checkout; source-blind роли получают отдельный материализованный каталог. Git worktrees и workspace manager отложены до параллельного выполнения.
- [constraint] Каждый execution получает явный абсолютный workspaceRoot; runner и workflow не выводят workspace из process cwd или глобального singleton.
- [direction] При реализации параллелизма добавить per-task worktrees и conflict coordination, сохранив существующий execution/runner contract.
- [decision] Каждая строка events.jsonl использует envelope schema_version/run_id/seq/time/type/payload; seq строго возрастает внутри run, события никогда не переписываются.
- [constraint] Неизвестная schema version, неизвестный event type, sequence gap или повреждённый committed record останавливает recovery fail-closed.
- [decision] Крупные prompts, outputs и logs хранятся отдельными evidence files; событие ссылается на относительный путь и SHA-256. Credentials и secrets в durable journal/evidence не записываются.
- [decision] Общий agent port — одновызовный RunTurn(ctx, request) плюс Close; request содержит optional opaque SessionRef, workspaceRoot, prompt, output schema и policy, result возвращает SessionRef, structured output и evidence reference.
- [constraint] Nil SessionRef начинает новую provider session, непустой ref продолжает её; adapter сам выбирает transport и process lifetime, provider-specific types/events не выходят за adapter package.
- [constraint] SessionRef служит только адресом для resume и не является durable workflow state или межролевым handoff; context cancellation обязана завершить turn и всё принадлежащее ему process tree.
- [decision] Agent adapters компилируются в Stepan и регистрируются composition root; внешний adapter plugin protocol и Go plugins не поддерживаются.
- [decision] Для каждого внешнего agent CLI адаптер задаёт minimum supported version, а не exact pin; версия ниже минимума отклоняется, более новая версия запускается без пересборки Stepan.
- [constraint] Точная обнаруженная версия и статус verified/unverified записываются до turn. Версия выше последней проверенной получает user warning и durable event, но сама по себе не блокируется.
- [constraint] Version check не заменяет protocol validation: отсутствие обязательного handshake/behavior, несовместимый envelope или нарушение общего runner contract завершает execution fail-closed на любой версии.
- [decision] Общая runner error taxonomy ограничена kind: unavailable, session_lost, policy_violation, invalid_output, canceled и failed; provider-specific code/message сохраняются как evidence/cause.
- [constraint] Adapter классифицирует наблюдаемый failure, но не выбирает retry, halt или новую session; это решение принимает workflow state machine и фиксирует durable event.
- [decision] Workflow role владеет canonical prompt, output JSON Schema и access policy; agent adapter выполняет transport/protocol translation и не меняет семантику роли.
- [constraint] Provider-specific prompt additions или настройки допустимы только в явно версионированном execution profile, чей fingerprint фиксируется до turn; скрытые adapter instructions запрещены.
- [decision] Verification strategy имеет три слоя: workflow tests с fake Runner, единая hermetic adapter conformance suite с fake/replay fixtures и live compatibility matrix agent×version×OS.
- [constraint] Verified status присваивается только конкретной CLI version/platform после live conformance; новая версия выше проверенной запускается как unverified с warning, новая платформа до live lifecycle/cleanup test не объявляется поддерживаемой.
- [constraint] Claude adapter допускается проектировать по официальной документации, но нельзя маркировать verified до теста реального CLI.
- [constraint] Продукт остаётся локальным native CLI и модульным монолитом; daemon, service API, database и собственный model runtime не входят в целевую архитектуру без отдельного решения.
- [event] Coaching elicitation завершён; начата дистилляция architecture spine.
- [decision] Runstore обеспечивает одного writer эксклюзивным OS lock; JSONL framing, torn-tail semantics и порядок durable publication evidence определены fail-closed.
- [decision] AccessPolicy является закрытым versioned deny-by-default контрактом Stepan; execution владеет enforcement, adapter только переводит политику в возможности CLI.
- [decision] Candidate snapshot строится как HEAD OID и полный будущий tree OID через изолированный Git index; проверки, verification, evidence и commit связываются с неизменным snapshot.
- [constraint] Статус verified принадлежит только точному tuple agent, CLI version, OS и CPU architecture после полного live conformance; любой иной tuple маркируется unverified.
- [constraint] Политика пользовательских extensions остаётся deferred и является release gate для execution profiles; текущий Codex baseline ADR 0001 не объявляется целевым default.
- [event] Architecture spine согласован с product brief, roadmap и текущими ADR; rubric, technology-reality и divergence reviewer gates завершились PASS. Spine финализирован.
