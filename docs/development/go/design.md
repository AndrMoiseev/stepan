# Типы, интерфейсы и пакеты

Применение: изменение типов, конструкторов, интерфейсов, зависимостей и границ пакетов.

## Правила

1. Обязательно соблюдайте правила глубоких модулей и импортов из [AGENTS.md](../../../AGENTS.md). Новый интерфейс должен скрывать связное поведение и уменьшать объём знаний, нужных потребителю.
2. По умолчанию определяйте интерфейс у потребителя и включайте только нужные ему операции. Существующий подходящий стандартный интерфейс предпочтительнее нового аналога.
3. По умолчанию возвращайте конкретный тип из конструктора. Возвращайте интерфейс, если скрытие реализации является частью контракта.
4. Передавайте обязательные зависимости явно через конструктор или параметры. Избегайте скрытой зависимости от изменяемых глобальных переменных.
5. Конструктор обязан обеспечивать заявленные инварианты либо возвращать ошибку. Если zero value поддерживается, его поведение должно быть полезным и согласованным с методами.
6. Экспортируйте только операции и данные, необходимые потребителям. Поля, изменение которых нарушает инвариант, храните внутри модуля.
7. Используйте pointer receiver для изменения состояния и типов, которые нельзя копировать. Для остальных выбирайте receiver с учётом семантики значения и согласованности методов.
8. По умолчанию используйте именованное поле для композиции. Embedding уместен, когда продвижение методов действительно входит в публичный контракт.
9. Выделяйте абстракцию по фактическим потребителям и устойчивому поведению. Дополнительный слой должен иметь объяснимую ответственность.
10. При изменении API обязательно проверьте потребителей, реализации интерфейса и направление зависимостей. Для изменения импортов обновляйте архитектурные ограничения согласно `AGENTS.md`.

## Исключения

Интерфейс может принадлежать поставщику, если это точка расширения или общий протокол нескольких потребителей. Дополнительная реализация ради теста не требует универсального DI-фреймворка. Новая зависимость должна решать конкретную задачу.

## При ревью

Проверьте, какие детали обязан знать потребитель, где поддерживаются инварианты и не возникла ли зависимость от flow у инфраструктуры. При изменении семантики nil, копирования или владения прочитайте [safety.md](safety.md).
