# Правила Go

Выбирайте темы после просмотра задачи и затронутого кода, включая вызывающие функции и зависимости, нужные для понимания контракта. Читайте только подходящие строки таблицы; при новых признаках добавляйте темы. Явное указание пользователем темы также служит поводом её загрузить.

| Признак задачи или кода | Документ |
| --- | --- |
| Написание или ревью Go-кода: имена, читаемость, комментарии | [Стиль](style.md) |
| Создание, передача, проверка или логирование ошибок; panic/recover | [Ошибки](errors.md) |
| Типы, интерфейсы, конструкторы, границы пакетов, зависимости | [Дизайн](design.md) |
| Nil, срезы, map, указатели, числовые преобразования; файлы, соединения и процессы | [Данные и ресурсы](safety.md) |
| Goroutine, каналы, общее состояние, context, таймауты, shutdown | [Конкурентность](concurrency.md) |
| Изменение поведения, требующее проверки; написание, ревью или диагностика тестов | [Тесты](testing.md) |

При разработке применяйте правила к изменяемому поведению. При ревью проверяйте diff и связанные контракты; расширяйте проверку за их пределы при обнаружении конкретного риска. В замечании указывайте правило и последствие. «Обязательно» обозначает требование; «по умолчанию» — рекомендацию с допустимым обоснованным отклонением. Предпочтение по стилю само по себе не доказывает дефект.

Версия Go, команды проверок, разделение тестовых наборов и архитектурные ограничения заданы в [AGENTS.md](../../../AGENTS.md) и имеют приоритет над общими рекомендациями здесь. Новые API сверяйте с версией в `go.mod`.

Для установки или запуска средств форматирования и тестирования читайте [инструменты](tools.md). Для сопровождения правил и сравнения с upstream — [происхождение](sources.md). Эти документы не требуется читать при каждой работе с кодом.
