# Стиль и имена

Применение: написание и ревью Go-кода, включая имена и комментарии.

## Правила

1. Обязательно форматируйте изменённые Go-файлы. По умолчанию используйте закреплённые `goimports` и `gofumpt`; команды находятся в [tools.md](tools.md).
2. Используйте `MixedCaps` для экспортируемых и `mixedCaps` для остальных имён; сохраняйте общепринятые сокращения (`ID`, `URL`, `HTTP`).
3. Выбирайте имена по роли в предметной области. Длина имени должна соответствовать области видимости; короткий индекс цикла не задаёт образец для поля структуры.
4. Проверяйте экспортируемое имя вместе с именем пакета. По умолчанию убирайте повторение, например `parser.Parser` заменяйте более предметным названием, если оно точнее отражает роль.
5. Сохраняйте одинаковое имя receiver в методах типа. Предпочитайте сокращение типа, а не `self` или `this`.
6. По умолчанию обрабатывайте ошибки и граничные случаи ранним выходом. При упрощении условий обязательно сохраняйте порядок вычислений и short-circuit поведение.
7. В литералах структур по умолчанию указывайте имена полей. Группируйте связанные объявления; избегайте перестановок, не связанных с задачей.
8. Комментарии объясняют контракт, причину ограничения или нетривиальное решение. Комментарии к экспортируемым сущностям начинайте с их имени; документируйте значимые побочные эффекты и ограничения.
9. Обязательно обновляйте комментарий при изменении описанного поведения. Очевидное действие не требует пересказа строк кода.
10. По умолчанию сохраняйте локальные соглашения, если они не противоречат обязательным правилам. Разбивайте длинные выражения по смыслу, без искусственного лимита аргументов или длины функции.

## Исключения

Сгенерированный код и имена, заданные внешним протоколом, следуют своему источнику. Совместимость публичного API может требовать сохранения существующего имени. Такие случаи не требуют массового переименования.

## При ревью

Проверьте, можно ли по именам и комментариям понять изменённый контракт, и не изменилось ли поведение при упрощении control flow. Замечания о вкусе отделяйте от нарушений согласованных требований.
