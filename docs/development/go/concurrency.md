# Конкурентность и context

Применение: goroutine, каналы, общее состояние, отмена, таймауты и завершение работы.

## Правила

1. Для каждой goroutine обязательно определите владельца, условие завершения и способ дождаться результата. Процессный фон должен принадлежать жизненному циклу приложения.
2. Каждое потенциально бесконечное ожидание должно иметь путь завершения: отмена, закрытие канала или гарантированное событие протокола.
3. Передавайте context вызывающего кода первым параметром в операции, поддерживающие отмену. Новый `Background` внутри такой операции требует отдельного обоснованного жизненного цикла.
4. Владелец производного context обязан вызвать cancel. Сам cancel сигнализирует отмену; ожидание завершения goroutine организуется отдельно.
5. По умолчанию передавайте context параметром. Используйте context values для метаданных операции; зависимости и параметры поведения передавайте явно.
6. Обязательно согласуйте владельца закрытия канала. Закрывайте канал только после прекращения всех отправок; при нескольких отправителях это обычно делает координатор.
7. По умолчанию указывайте направление канала в параметрах. Размер буфера должен следовать протоколу и требуемому ограничению очереди.
8. Защищайте общее изменяемое состояние единым протоколом синхронизации. Для обычной map конкурентное чтение допустимо, если запись отсутствует и публикация данных безопасна.
9. Под блокировкой поддерживайте весь инвариант. По умолчанию выносите I/O и неизвестные callback за критическую секцию, сохраняя корректность состояния.
10. Выбирайте mutex для совместного состояния, канал для обмена и координации. Atomics подходят для доказуемо независимых простых операций; несколько atomics сами по себе не обеспечивают общий инвариант.
11. Ограничивайте число одновременно выполняемых задач, когда объём входа не ограничен. Политика отмены и распространения ошибок должна быть явной.
12. Обязательно проверяйте shutdown: прекращение приёма работы, сигнал отмены, разблокирование ожиданий и ожидание завершения. Освобождайте ресурсы после прекращения их использования.

## Исключения

`ctx.Done()` нужен там, где отмена должна прервать ожидание; он не обязателен в каждом `select`. Передача указателя по каналу допустима при передаче владения, неизменяемости или синхронизации. `sync.Map` выбирайте по характеру доступа, а не просто по наличию goroutine.

## При ревью

Проверьте отмену до начала и во время работы, ранний выход потребителя, порядок закрытия и ожидания. Для проверки этих сценариев загрузите [testing.md](testing.md); отсутствие гонок в одном запуске не доказывает корректность протокола.
