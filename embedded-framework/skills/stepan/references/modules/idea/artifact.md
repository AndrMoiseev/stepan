# `idea.md` artifact contract

Keep every required section non-empty. Additional useful sections are allowed
only when they remain within product framing and are grounded under the shared
idea rules.

```text
# Idea
## Problem
## Goal
## Target user
## Expected outcome
## Scope
### In
### Out
```

Use the sections as follows:

- `Problem`: describe the present need, constraint, or undesirable situation
  without presenting the proposed implementation as the problem.
- `Goal`: state the product change intended to address the problem.
- `Target user`: identify the intended user class and relevant usage context.
- `Expected outcome`: state the observable user or product result, not merely
  that the proposed implementation exists.
- `Scope / In`: bound the capability included in this change.
- `Scope / Out`: record at least one explicit exclusion or boundary.

Keep the sections concise, mutually consistent, and distinct. Do not use
assumptions, `TBD`, `unknown`, or similar placeholders to keep a section
non-empty.
